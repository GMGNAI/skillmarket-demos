# MemeX Agent · BSC 链上尽调

把合约地址丢进对话框，六项确定性规则技能跑一遍，出一个 0-100 的综合分，
**每一分怎么扣的都写在脸上**。不是 LLM 打的分。

在线演示：https://gmgnai.github.io/skillmarket-demos/memex/

---

## 这个 demo 是什么

一个**单文件、纯前端**的链上尽调面板。没有后端、没有构建步骤、没有任何第三方库 ——
`static/index.html` 一个文件就是全部，用你自己的 GMGN API Key 直连官方 OpenAPI。

六项技能全是 `skills.js` 里的确定性规则：

| 技能 | 权重 | 看什么 |
|---|---|---|
| CA 安全审计 | 34% | 蜜罐 / 买卖税 / 开源 / 弃权 / LP / 池深 / 前十控盘 / Dev 画像 —— 19 类检查 |
| 聪明钱结构 | 22% | 聪明钱·知名钱包·蓝筹 vs 机器人·捆绑·狙击·新钱包，Top100 盈亏与净流 |
| 前排地址 | 19% | 前 70 个买入者的**当前**状态：清仓 / 加仓 / 转出 / 仍持有 |
| K 线形态 | 15% | EMA 交叉 · 回归斜率 · ATR 波动率 · 量价背离 · 区间回撤 |
| X 叙事热度 | 10% | 项目方时间线 + 叙事源推 + KOL 名单扫 CA 提及 |
| Binance Alpha 催化剂 | 封顶加减分 | 上没上 Alpha、上了多久、还在不在架上 |

Alpha 催化剂**不进加权平均** —— 大部分盘都没上 Alpha，算进平均只会稀释真正有
区分度的技能，所以它作为封顶的加减分叠加在加权之后。

## 怎么用

1. 打开在线演示，或把 `static/index.html` 下载下来**双击打开**（单文件，没有依赖）
2. 到 [GMGN API 管理页](https://gmgn.ai/ai?chain=bsc&tab=api_management) 申请一个 API Key
3. 面板里 设置 → 数据源 → 填进去
4. 把合约地址、钱包地址、`$SYMBOL` 或 X 账号丢进对话框

Key 只存在你自己浏览器的 `localStorage` 里。这个页面**没有后端**，所以除了
`openapi.gmgn.ai` 之外，它没有任何地方可以把 Key 发出去。

### 只填 API Key，不要填私钥

官方把端点分两类：`authExist` 只需 `X-APIKEY`（查询类），`authSigned` 还要
`X-Signature`（Ed25519 私钥签名，交易类）。**这个 demo 只实现前者** ——
代码里一行签名逻辑都没有，界面上也没有私钥输入框。

私钥是交易签名凭证，拿到就能代你下单撤单。分析工具不需要任何写操作，
所以连「能签名」这个能力都不该存在。**即使你的 API Key 泄露，最坏后果是别人耗掉
你的读取配额，动不了你的钱。**

## 浏览器直连能做到什么，做不到什么

这一点必须说清楚，否则你会以为是坏了。

`openapi.gmgn.ai` 返回 `Access-Control-Allow-Origin: *` 并允许 `X-APIKEY` 头，
所以纯浏览器能直连官方 OpenAPI。但公开端点 `gmgn.ai` **不返回 CORS 头** ——
浏览器里根本打不通，localhost 也一样。

于是有一批数据在纯前端模式下拿不到：

| 数据 | 状态 | 原因 |
|---|---|---|
| 代币信息 / 安全 / 持有人 / K线 / 热门榜 | ✅ 官方 API | |
| 钱包画像（胜率、持仓周期、盈亏分布）| ✅ 官方 API | 这是接 Key 最大的动机 —— 公开接口这些字段一律返回 0 |
| 风险统计（老鼠仓 / 捆绑 / 狙击 / 新钱包率）| ❌ 不可用 | 官方无对应端点 |
| 前排地址 | ❌ 不可用 | 官方有 `token_top_traders`，但那是「顶级交易者」，我们要的是「最早买入者」的状态机 —— 语义不同，不能替换 |
| 成交流水 | ❌ 不可用 | 官方无对应端点 |
| X 叙事 / Web2 叙事源 | ❌ 不可用 | 那几个站点也不返回 CORS 头 |

**拿不到的项不会被算成好消息。** 这一条是刻意做的：`f(undefined)` 给 0，
如果不管，「Dev 持仓 0%」和「狙击占比 0%」就会被读成「Dev 已清仓」「狙击盘已出清」，
让一个查都没查过的盘看起来很干净 —— 比标成「数据缺失」危险得多。
所以缺失的字段一律记入 `unknown` 并在卡片上明写；蜜罐检测缺失时分数封顶 59，
结论直接写「关键项未查到，不足以判断安全性」。

想要完整六项，用 [Chrome 扩展或本机服务](https://github.com/Edwardchennnn/MemeX-Agent)
—— 那两种形态是特权/服务端取数，不受浏览器同源策略限制。

## 默认不调用任何 AI

六项技能一行 LLM 请求都没有，所以零 API 成本、结论可复现（同一份数据必然同一个分数）。
AI 接口预留了三个接入点（意图理解 / 结论撰写 / 追问），但有一条铁律：
**AI 不参与打分。** 开不开 AI，同一个 CA 的评分完全一致。

注意「不调 AI」不等于「不联网」—— 打分不需要网络，但链上数据得实时抓。

## 这个单文件是怎么来的

上游仓库是多文件的（ES 模块 + 经典脚本 + 外部样式和字体）。本仓库的 pre-commit
钩子只把 `<demo>/static/index.html` 同步到 Pages 发布目录，`static/` 下的兄弟文件
不会被同步，所以任何外部引用在线上都会 404 —— 必须打成真正的单文件。

两个脚本负责这件事（在上游仓库的 `tools/`）：

- `bundle_demo.py` 把 15 个 ES 模块打成一个经典脚本。它**只覆盖本项目实际用到的
  import/export 形态**，遇到没见过的写法报错退出而不是悄悄产出坏包
- `build_demo_page.py` 内联样式 / 词典 / 图表 / 模块 / 主字体，并自检没有残留的
  绝对路径引用

打包产物与真实 ES 模块逐个比对过：**导出名 15/15 一致，函数体逐字一致 153/153**。

## 不是投资建议

输出的是尽调事实和风险信号，不是买卖指令。**评分高不等于安全，评分低不等于必跌。**
上游数据来自 GMGN，数据被操纵时结论也会跟着错 —— 这个工具能标注数据走的哪一路，
但没法验证上游是否诚实。
